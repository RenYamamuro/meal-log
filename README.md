# MEAL LOG（食事・PFC記録アプリ）

食べたものを記録して、カロリーと PFC（たんぱく質・脂質・炭水化物）が
1日の目標に対してどれだけかを見るための自分用Webアプリ。
LIFT LOG と同じく素の HTML + CSS + JavaScript の1ファイル構成で、
データはブラウザの `localStorage`（キー `meal-log-v1`）に保存される。
Googleでログインすると、LIFT LOG と同じ Firebase を通して端末どうしで同期される（ログインしなくても使える）。

## できること

1. **今日の合計** — フィットネスアプリ風のリング（外から カロリー・P・F・C。目標を超えた分は2周目として重ねる）、
   残り量、PFCバランス（実際と目標の比較）。日付はタップで iPhone 標準の日付選択が開く
2. **食事ごとの記録** — 朝食・昼食・夕食・間食。食品をタップすると量の変更・食事の付け替え・削除ができる。
   左へスワイプで削除（引き切るとそのまま削除）。消したあと数秒は「元に戻す」が出る
3. **食品から選ぶ** — 内蔵の約50品（主食・肉魚・卵大豆乳・野菜果物・惣菜外食・飲み物間食）から検索 or カテゴリで選ぶ。
   量は「単位」の倍数（0.5刻み、直接入力も可）。「最近」に使った順で並ぶ
4. **手入力とマイ食品** — 栄養成分表示を写して登録。kcal を空けると P×4 + F×9 + C×4 で計算。
   「マイ食品に保存」すると次から選べる（目標タブで削除できる）。記録した食事（写真で判定したものなど）も、
   タップして「マイ食品に登録」すればマイ食品になる（1単位の値をそのまま写す。同じ名前と量のものがあれば登録済み）
5. **履歴** — 直近7日 / 30日のカロリーとたんぱく質の棒グラフ（点線が目標、目標の1.1倍を超えた日は薄く表示）、
   記録した日の平均と PFC バランス、日ごとの一覧（タップでその日へ）
6. **目標** — 性別・年齢・身長・体重・活動量・目的から自動計算、または自分で直接入力
7. **クラウド同期** — 「目標」タブから Google でログインすると、どの端末でも同じ記録・目標・マイ食品が出る
8. **書き出し・読み込み** — JSON でバックアップ
9. **写真で判定** — 追加画面の「写真で判定する」で食事の写真を撮る／選ぶと、Claude（Opus 5.5）が料理ごとの量と
   kcal / PFC を見積もる。品目ごとにチェックを外したり、量を 0.5 倍刻みで直したりしてから、まとめて記録する

## 写真で判定（AI）

`photo-ai.js`。Claude API をブラウザから直接呼ぶ（Anthropic の TypeScript SDK を jsDelivr から読み込み、
`dangerouslyAllowBrowser: true`）。サーバーは持たない。

- **API キー**：本人が Anthropic のコンソールで発行したものを「目標」タブで入れる。`meal-log-ai-v1` に保存し、
  クラウド同期・書き出しには含めない（端末ごとに入れる）
- **モデル**：`claude-opus-5-5`。深さ（`output_config.effort`）は設定で「浅い（low）」「標準（medium）」を切り替える。初期値は low
- **出力**：structured outputs（`output_config.format` の JSON スキーマ）で、`items[]`（name / amount / kcal / p / f / c / confidence）と `note` を受け取る
- **断られたとき**：`fallbacks: "default"`（beta `server-side-fallback-2026-07-01`）で、サーバー側で別のモデルが引き継ぐ。
  それでも断られたら「判定できませんでした」と出す
- **写真**：送る前に長い辺を 1280px に縮める（JPEG）。アプリには保存しない
- **料金の目安**：返ってきた `usage` のトークン数から計算して、結果画面と「今月の判定」に出す（$4 / $20 per MTok、1ドル150円で換算）。
  実際の請求は Anthropic のコンソールで確認する
- 判定結果の記録は `est: true`（目安）として保存し、`unit` には「茶碗1杯 約150g」のような見積もった量が入る

## 見た目（iOS 純正アプリに寄せている点）

- 文字は iOS の標準の段階（本文17・補足13・大見出し34、太さは本文400／見出し600）。単位は rem で、iPhone では `-apple-system-body` から本文の大きさを取るので、設定の「文字サイズ」に追従する。LIFT LOG・サブスク管理（本文15px）とはここだけ違う
- テーマは「目標」タブの「表示」で 自動／ライト／ダーク を選ぶ（`meal-log-theme`、端末ごとで同期しない）。自動は端末の外観に合わせる。ダークの色は `html[data-dark]` に置き、付けるかどうかは `<head>` のスクリプトが描き始める前に決める（一瞬白く光らないように）
- 押せる部分は 44pt 以上。見た目を小さくしたい部品は `::after` で押せる範囲だけ外側に広げている
- シートは画面の端から 8px 浮かせて四隅を丸め、見出しの行の左に「キャンセル／戻る」、右に主な操作（「追加」など）か「×」。削除は本文の下の赤い文字の行。選ぶ印は丸いチェック、オン／オフはスイッチ
- 大きい見出しが画面の外に出ると、上のバーがすりガラスになって小さい見出しが出る（LIFT LOG と同じ）
- 下のタブは画面の端から浮いたカプセル型（LIFT LOG と同じ）。右に＋を同じ高さの丸として並べる。＋はどのタブでも押せて、押すと「今日」に移って追加画面を開く
- 一覧の区切り線は左端から少し内側で始め、タップで先へ進む行には右端に「＞」
- 左スワイプの削除と、下から出るシートの取っ手・引き下ろして閉じる動きは、サブスク管理と同じ作り。
  手入力の途中は引き下ろしでは閉じない（書いた内容が消えるため）
- Web では出せないもの：タップの振動（iPhone の Safari は非対応）、SF Symbols（規約で Apple の OS 用アプリ以外は不可。
  「＞」などは自前の SVG）、Liquid Glass の屈折（すりガラス風まで）

## 目標の計算

- 基礎代謝：Mifflin-St Jeor 式（男性 `10×体重 + 6.25×身長 − 5×年齢 + 5`、女性は `− 161`）
- 消費カロリー：基礎代謝 × 活動係数（1.2 / 1.375 / 1.55 / 1.725）
- 目標カロリー：減量 −400 / 維持 ±0 / 増量 +300 kcal
- P：体重 × g/kg（初期値 2.0）、F：カロリーの %（初期値 25%）、C：残り全部

## 食品の値について

`index.html` の `FOODS`。素材は日本食品標準成分表（八訂）の100gあたりの値を1単位に換算したもの。
`est: true`（画面では「目安」）の惣菜・外食・市販品はよくある値で、店や商品でかなり変わる。
記録には追加した時点の値を写して保存するので、`FOODS` を直しても過去の記録は変わらない。

iPhone では Safari とホーム画面のアプリで保存場所が別になる。ログインしていれば同期でそろう。

## クラウド同期

`firebase-sync.js`。LIFT LOG と同じ Firebase プロジェクト（`workout-app-27d33`）と同じログインを使う。
セキュリティルール（LIFT LOG の `firestore.rules`）は「本人は自分の `users/{uid}/` 以下を何でも読み書きできる」
なので、MEAL LOG のために Firebase コンソールで変える設定は無い。

- 保存先: `users/{uid}/mealDays/{YYYY-MM-DD}`（1日分の記録）と `users/{uid}/mealSettings/main`（目標・からだ・マイ食品）。
  LIFT LOG の `logs` / `photos` とは別の場所なので混ざらない
- 記録や目標を変えるたびに自動で同期（目標の数字は打つたびに変わるので、1.2秒待ってまとめて送る）。
  アプリに戻ってきたとき（画面が表に出たとき）にも同期して、ほかの端末の記録を取り込む。手動の「今すぐ同期」もある
- **1日＝1ドキュメント**にしているのは読み取り回数を抑えるため。LIFT LOG のように毎回全部を読むと、
  食事は件数が多いので Firestore の無料枠（1日5万回の読み取り）にいずれ届く。
  2回目からは、前回のあとにクラウドで変わった日だけを `syncedAt`（サーバーの時刻）で絞って読む
- 同じ日を2つの端末で変えたときは、あとから変えた方（`updatedAt`）がその日まるごと勝つ
- 削除は「空の日 `[]`」を送ることで伝える。だから記録を全部消した日も `days` に `[]` で残している
- まだ送っていない日は `dirtyDays`、設定は `settingsDirty` に印が残る。オフラインで付けた記録も次の同期で送られる
- 書き出しファイルを読み込むと、その内容を最新として扱い、同期で他の端末にも広げる
- 「最近使った食品」は端末ごと（同期しない）

## 手元で動かす

```
python3 -m http.server 8765
```

をこのフォルダで実行して http://localhost:8765 を開く。`index.html` を直接開いても動くが、
Service Worker（オフライン）は効かない。

## ファイル

- `index.html` — アプリ本体（HTML / CSS / JS すべて）
- `firebase-sync.js` — クラウド同期（Firestore + Googleログイン）
- `photo-ai.js` — 写真で判定（Claude API）
- `sw.js` — オフライン用の Service Worker（ネットワーク優先 + キャッシュ）。中身を変えたら `CACHE` の版を上げる
- `manifest.json`・`icons/` — ホーム画面に追加したとき用
- `fonts/` — LIFT LOG と同じ丸ゴシックの書体
